# ADR-003: Bot Installation Path - AppData\Local

**Date:** 2026-08-30  
**Status:** ACCEPTED  
**Author:** Claude (Project AI)

## Context

The bot requires installation of runtime files (bot.py, config.json, logs) somewhere on the user's system. Three primary locations were considered:

1. **AppData\Local** - User-specific hidden directory (`$env:USERPROFILE\AppData\Local\BATCRelayBot`)
2. **Program Files** - System-wide application directory (`C:\Program Files\BATCRelayBot`)
3. **Home Directory** - User's documents (`$env:USERPROFILE\BATCRelayBot`)
4. **Current Directory** - Wherever user runs install command

Additional context: Bot requires sensitive config (Discord token), needs read/write access for logs, and Python/ffmpeg are also installed per-user.

## Decision

We chose **AppData\Local** as the bot installation path.

## Rationale

### Why AppData\Local?

1. **Per-user isolation** - Each Windows user gets separate bot installation
2. **No admin rights required** - Users can install without administrator privileges
3. **Standard Windows practice** - AppData\Local is standard for user app data
4. **Hidden from user** - `AppData\Local` is hidden by default, less visual clutter
5. **Consistent with Python/ffmpeg** - Both are installed per-user, AppData\Local keeps related tools together
6. **Backup/roaming** - Separate from system files, easier to backup
7. **Security** - Hidden directory makes config.json less visible to non-technical users
8. **Clean uninstall** - Entire `BATCRelayBot` folder can be deleted for clean removal

### Why NOT other options?

- **Program Files** - Requires admin rights for installation, violates per-user principle
- **Home Directory** - Makes bot visible in user's home, clutters user's space
- **Current Directory** - Depends on where user runs command, unpredictable and fragile

## Consequences

### Positive
- Clean separation from system and user-level programs
- No admin rights required
- No cluttered home directory
- Consistent with Windows conventions
- Easier system cleanup (single folder to delete)
- Bot files isolated from other projects
- Automatically backed up if user uses system backup

### Negative
- Hidden from casual user browsing (may not realize where files are)
- Users need to know full path to access files manually
- Not visible in traditional "Program Files" (may confuse some users)
- AppData\Local can get large if logs accumulate

## Related Decisions

- ADR-002: PowerShell Module - bot files live separate from module
- ADR-004: Manual config - config.json in same location for easy access

## Alternatives Considered

1. **Program Files** - Rejected for admin requirements
2. **User's home directory** - Rejected for cluttering user space
3. **Temp directory** - Rejected (not persistent, cleaned up by Windows)
4. **OneDrive/cloud sync** - Rejected (could interfere with file operations)

## Implementation Details

### Installation Path Structure

```
$env:USERPROFILE\AppData\Local\BATCRelayBot\
├── bot.py                      # Discord bot (copied from module)
├── requirements.txt             # Python dependencies (copied from module)
├── config.json                  # User config (generated by Install-BATCRelayBot)
├── config.example.json          # Template (copied from module)
├── bot.pid                      # Process ID (generated at runtime)
├── stop.signal                  # Shutdown signal file (generated at runtime)
└── logs/
    ├── bot_output.log          # Bot stdout
    └── bot_error.log           # Bot stderr
```

### Typical Path Example

```
C:\Users\JohnDoe\AppData\Local\BATCRelayBot\
```

### Environment Variable

Users can access this path via PowerShell:

```powershell
$botPath = "$env:USERPROFILE\AppData\Local\BATCRelayBot"
cd $botPath
Get-ChildItem  # View files
```

## User Communication

In README, we clearly state:

```
Bot files are installed to:
$env:USERPROFILE\AppData\Local\BATCRelayBot

This location is:
- Hidden from normal file browsing (type path in explorer address bar)
- Per-user (each Windows user has separate bot installation)
- Backed up automatically if you use system backup
- Easy to remove: simply delete the BATCRelayBot folder
```

## Impact on Other Components

1. **Install-BATCRelayBot** - Creates this directory, copies files here
2. **Start-BATCRelayBot** - Looks for config.json and bot.py here
3. **Stop-BATCRelayBot** - Looks for bot.pid here
4. **Get-BATCRelayBotStatus** - Looks for bot.pid and logs here
5. **Uninstall-BATCRelayBot** - Deletes this directory

## Migration Path

If users had bot in other location (from v1.0.0), they must:
1. Run `Uninstall-BATCRelayBot` (old location)
2. Run `Install-BATCRelayBot` (installs to AppData\Local)
3. Reconfigure by running `Install-BATCRelayBot` again

## Notes

- PowerShell module itself lives in: `$env:USERPROFILE\Documents\PowerShell\Modules\BATCRelayBot\`
- This is different from bot runtime files (AppData\Local)
- Separation of concerns: Module = code, AppData\Local = data
